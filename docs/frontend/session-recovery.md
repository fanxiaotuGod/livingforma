# Session recovery and protected writes

LF-210 repairs stale-session writes on the isolated `fix/session-recovery` release branch. The backend retains strict Origin, session, authorization and CSRF checks. This change introduces no automatic write retries or provider calls.

`lib/session-client.ts` is the shared browser request boundary. Every protected user write obtains a fresh, uncached `/api/session` response first. It sends exactly one write with the current CSRF token only when the authenticated account still matches the account that initiated the action. A different account or anonymous session sends no write. A 401 or 403 refreshes session state and reports the failure; it never replays the rejected request.

This boundary covers record actions, proposals, space creation, tool registration/invocation, media session creation/transcription/observation and logout. Local test sign-in is an explicit authentication transition with its own preflight. The only cleanup exception is a best-effort media-session DELETE with the original token and keepalive: unloading a device must not fetch a new identity, rotate a device-bound token or replay work.

Session changes synchronously stop local media and invalidate outstanding protected responses. A changed account or explicit authentication failure clears privileged snapshots, closes SSE, and hides the old account's controls while fresh data loads. A token rotation for the same account retains business forms and their drafts while refreshing identity and data. The new explicit user operation can use the new token; older in-flight operations cannot report success. Navigation also advances a synchronous page revision, so navigating away and back does not revive old writes or private reads.

Draft keys use `lf-draft:v2:<encoded account ID>:<space/component key>`. New-space title and prompt use the same account isolation. Storage changes occur when the user edits or a valid operation succeeds, so changing a storage key cannot copy the previous account's draft into the next account. Logout does not delete drafts. An existing legacy unscoped Owner command is migrated only when an authenticated, confirmed Owner opens that same space. Other legacy unscoped drafts have no trustworthy account attribution and are not loaded into another account's view.

Twelve targeted request-boundary tests cover fresh same-account tokens across write endpoints, account/anonymous changes, rejected-write non-replay, stale successful writes after account changes or navigation, private-read rejection, session-read ordering, out-of-order same-account preflights, invalidated pending preflights and successful logout. Five existing media transport tests also pass. TypeScript and the web production build pass; QA LF-211 independently passed all 15 real HTTP/PGlite/Chrome regression scenarios against the final build, including same-account parallel writes and stale logout.
