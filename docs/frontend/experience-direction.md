# LivingForma 前端体验方向

状态：2026-10-03 用户方向已确认；交互、组件 schema 与接口细节仍是候选。当前没有可运行前端。本文件只规划体验，不证明功能已实现；公共契约由 coordinator 定稿。

## 一句话画面

LivingForma 是能与空间主人对话、在获准时观察当前场景、持续改变同一个网站的 Jarvis 式界面。用户打开稳定链接先看见**网站本身**：内容、记录和可执行操作，不是聊天产品的侧栏。读书记录与习惯打卡是开场样例，不是生成器的类别上限。自然语言生成的仍是服务端验证的受限 AppSpec、状态与能力引用；“可以变成许多 App”不表示运行模型生成的任意代码。

用户确认的两条核心价值是**前端可玩、可变形**与**后端 Pi 可受控创建并复用工具**。前端应主动梳理读书、习惯、预算、任务等不同场景所需的丰富交互，先实现可信且可复用的组件/变体；Agent 依照场景选择组件与能力并组合，而不是换标题的固定模板或只有 CRUD 的表格。Pi 提出的新工具仍经后端校验、授权和注册，不能把模型建议直接当作可执行代码。

访客无需登录即可浏览公开空间的可公开内容；尝试新增或修改记录时才进入 Google 登录，再由服务端按该空间权限决定是否允许写入。MVP 仅此空间的 Owner 看见编辑 orb；这里的“admin”就是 Owner，不另设可委派管理员角色。普通已登录参与者仍只看 App，不获得 orb。公开快照的字段裁剪、空间可见性和登录后的返回位置须由共享契约明确，不能靠前端隐藏按钮当授权。

## 演示分镜

1. **访客进入。** 打开读书空间，直接看到书籍卡片。首版封面由书名、稳定色彩和排版生成，不依赖外部图片。未登录可浏览；点击独立的“登录后添加书籍”提示时保存返回位置与输入意图，Google 登录后重新取得权限再允许提交。提示入口不是已授权的业务动作，匿名请求绝不写入。
2. **Owner 改造。** 空间 Owner 左上角的小圆 orb 被点击后移动并放大到画面中心，露出简洁的文字输入与麦克风入口。Owner 说或输入“让封面更突出，给已读书加评分并按评分排序”。提交后编辑面板收回左上角；原网站仍可浏览、输入与使用。
3. **真实发布。** orb 在角落显示由后端确认的“理解需求 → 校验变更 → 发布界面”阶段，而非虚构百分比。发布成功后，书籍卡片从原身份平滑变为 cover/hero 等被允许的样式，新增评分；旧书、记录 ID 与 URL 保留。普通记录新增/更新只对相关内容给局部反馈，不让整页再次变形。
4. **另一种 App。** 同一运行时创建习惯空间，视需求显示打卡列表或 calendar-grid。两个空间的数据与定义隔离；参与者写入后，在线浏览者看到更新。公开读与受保护写的权限边界贯穿两个空间。
5. **下一里程碑。** Owner 在本地设备明确开启摄像头与语音会话，让 Gemini 根据经同意的画面内容理解场景，ElevenLabs 输出语音回应，再提出受控网站变更。摄像头/麦克风的开关、预览与停止状态只属于本设备会话；SSE 只同步已授权的 App 定义与业务状态，不广播设备流，也不令其他浏览器远程自动开机。具体上传/保留策略需与 Agent、Backend 和隐私设计确认。

分镜是目标体验，不代表 API、语音、视觉或实时同步已经接通。若演示使用固定 AppSpec fixture、MSW、BroadcastChannel 或 mock SSE，必须在说明中标为模拟；其中任何一个都不能作为云端持久化或真实跨设备多人同步的证据。

## Owner orb 状态与输入安全

| 状态 | 可见行为 | 关键约束 |
| --- | --- | --- |
| 收起 | 左上角小圆，有明确可读名称、未读状态和键盘焦点样式 | 仅有效空间定义编辑权限可见；移动端避开安全区和内容遮挡 |
| 展开 | 圆形连续放大到中心，提供文本、麦克风和当前请求上下文 | 作为对话框管理焦点；打开聚焦输入，Tab 留在面板，Escape 关闭并返回 orb 焦点；屏幕阅读器得到标题/说明 |
| 本地采集 | 麦克风或摄像头由该用户明确点开，显示采集中的视觉和文字提示 | 浏览器权限拒绝、设备失效可恢复到文字；关闭、登出或会话终止即停止本地轨道；不由远端事件触发 |
| 已提交 | 输入面板收回角落；网站维持最后一个有效版本 | 保留请求 ID 与草稿直至服务端接收；不得把动画结束当成发布成功 |
| 处理中 | orb 小范围显示真实阶段，点击可看进度/错误 | 阶段来自可核验的服务端事件；无阶段证据时用不确定进度，不伪造内部推理或精确百分比 |
| 成功或失败 | 成功后出现新定义；失败时旧站继续，展开可恢复草稿与错误 | 409/unsupported/额度耗尽不清除已编辑内容；必须可重试或修改请求 |

提交快捷键、语音转写确认以及关闭时如何保留未提交草稿需要原型测试；默认以按钮为可靠提交入口，避免输入法组合键造成误提交。独立的访客登录提示不是 orb：它只处理业务写入认证与返回原操作。Owner 权限变化或会话失效时立即移除 orb、停止本地采集并清理身份相关缓存。

## 可扩展视觉语法（待共享契约）

原 form/list/cards/counter 是起步能力，不是永远的产品上限。用户已接受继续设计 cards 的 `cover / compact / hero` 变体、list 的 `dense / comfortable` 密度、受限强调规则、`calendar-grid` 和约 4–6 套枚举化皮肤 token。它们应由有限、可校验的组件/属性组合表达，而非 Planner 写任意 CSS、JSX 或脚本。每项的字段引用、排序/强调语义、色彩 token、移动端降级和无障碍规则尚待 coordinator 接受共享 schema；前端不能把候选值声称为现有支持。

为让 Agent 安全拼装，组件注册项需描述适用场景、输入数据/字段类型、可绑定动作、变体与布局约束、权限和空/错/加载状态、动效身份及可访问性/移动端降级。前端主动提出能覆盖多类场景的组件并验证它们；具体 manifest/schema 由共享契约确定，未注册的组件不能被 Agent 当成已上线能力。

选择视觉配置时优先让布局服从数据：读书 `cover` 卡在 v1 用确定性的标题、色彩 token 与字形构成文字封面，长标题/空列表都有可读回退；真实外部书封面图片留待受控资源/字段 schema 扩展，不是首版验收前提。习惯日历应明确日期与完成状态。强调规则只能引用已存在字段与受限比较，颜色之外还用文案、形状或位置表达状态。有限皮肤改变排版与色彩，不改变记录/字段/组件身份，也不泄露空间私有数据。新增组件须走注册、验证、降级和真实验收，不能把效果图当作运行时能力。

## 版本、同步与动画

只把服务端已发布的完整有效快照放入呈现层。并发 snapshot 请求采用“最新有效结果胜出”：用请求序号及 `eventCursor`/定义和状态版本拒绝过期响应；若两个快照的版本维度不可比较，则重拉权威快照。此规则仅防止旧画面覆盖新画面，**不能丢弃已发出的业务 mutation、服务端确认、错误回执或用户草稿**。mutation 需按 `requestId` 独立追踪；冲突时保留输入并请用户复核。公开与登录用户的快照不能跨身份共享缓存。

定义发布才触发跨组件的连续变形：稳定组件 ID 对应同一语义时用 Motion 的位置/尺寸过渡；身份或含义改变则清晰替换，不强作 morph。业务记录事件只更新涉及的记录/计数，避免把每次打卡渲染为整站再生成。切换过程中焦点留在仍存在的控件；若控件消失，移动到新标题或首个可操作项，并用短句 `aria-live` 通知。`prefers-reduced-motion` 时保留状态反馈、缩短或关闭位移动画；交互和数据提交不等待动画。

## 前端验证顺序（建议，不是日程承诺）

先做 Owner/访客/参与者三视角和 orb 的设计分镜，再用静态有效规格建立 renderer 与 morph 实验场；随后接真实后端快照、持久业务动作、权限和事件恢复。以真实 Gemini/ElevenLabs 接口、设备授权和费用边界完成语音/视觉里程碑。固定 fixture、MSW、BroadcastChannel 只证明局部组件或协议模拟可工作；发布“多人同步已实现”必须有服务端持久数据与两个独立客户端的证据。
