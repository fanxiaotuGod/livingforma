## Changed behavior

All protected writes now pass through `lib/session-client.ts`: uncached session preflight, initiating-account match and the freshly returned CSRF token. Same-account rotation allows one current write. A changed or anonymous identity sends zero writes. Rejected writes are reported, never automatically retried. The old media-session DELETE remains a best-effort cleanup with its original token; it does not renew or replay a device session.

Session, intent and navigation revisions reject late read/write results explicitly. Identity changes or authentication rejection clear privileged state, close SSE and stop devices; same-account token rotation preserves business forms while stopping old media/in-flight work. A late session GET cannot restore the pre-logout identity. Concurrent same-account preflights may use newer accepted identity evidence without failing an unrelated current write.

Drafts are scoped by account and space/component, including new-space title/prompt. Switching accounts does not copy the prior draft into a new storage key; successful current operations clear both storage and displayed values. Logout preserves drafts for their originating account. Existing unscoped Owner commands migrate only through the currently confirmed Owner view. Blocked browser storage does not crash the editor.
