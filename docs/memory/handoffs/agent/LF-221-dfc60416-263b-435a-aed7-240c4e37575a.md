Implemented in the primary checkout; no live provider/deployment claim. `@livingforma/agent` now exports `generateSite: SiteGenerator`. Coordinator/Backend must wire it into the existing `buildApp({siteGenerator})` server path. See [runtime documentation](../../../agent/generated-sites.md).

The generator uses one generic `submit_site` Pi/Gemini tool to author custom HTML/CSS/JS, schema/actions and a model outline. It does not route intents to whole-app templates. Existing schema/evolution and data remain host-authoritative, and the generic generated surface keeps its old ID. Current/repair private defaults are stripped again. The legacy 60-module planner excludes generated-site and redirects existing generated-source changes to the studio.

Actual Pi message_update/toolcall events expose only bounded changed source fields and validated outline→Progress.ui. Thinking, plain assistant text, raw deltas and unrelated tool metadata are excluded. Google Pi1.0.1 may deliver function arguments as a complete snapshot; no fabricated typing is used. Outline has no executable markup and is safe wireframe metadata.

One invocation = at most one provider reservation/6000outputtokens/60seconds. Missing durable budget fails even in development, with no JSON fallback. Existing verified-free/model/day/minute/concurrency limits remain. A well-shaped but statically invalid candidate returns for LF220 to reject and consume its one shared static/browser repair; generator does not retry internally. Malformed output fails truthfully. The same exported function consumes a concrete repair proposal/diagnostics when the host authorizes it.

Verification: `pnpm exec vitest run packages/agent/src` **96/96**, with 17newtests through real Pi and a fixture Google event stream; `pnpm typecheck` passes. Tests cover three distinct source interactions, actual outline/source checkpoints, private defaults/evolution, static repair, malformed output, source bounds/secrets, cancellation during reservation and late results, concurrent budget protection and the studio boundary. Source is parsed, never evaluated on the host. Existing uncommitted module work is preserved.

No new dependency, .env read, real provider call, private ledger mutation, paid resource, advanced sandbox bypass reproduction, Git commit/push or deploy. Real model/browser acceptance belongs to coordinator/independent QA. LF225 is the separate follow-on for generated backend tools and authorized existing tool bindings; LF221 does not pretend those services already exist.
