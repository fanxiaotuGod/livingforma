## 2026-10-03 · 当前目标：页面、工具和动态界面一起生成

AI 生成新的浏览器页面逻辑，也能生成新的后端 JavaScript 工具代码、输入输出约束和代表性测试。宿主验证并运行测试后注册版本，Owner 明确发布时启用，网站通过精确版本绑定调用和复用。Pi 编排模型与工具，宿主负责隔离、权限、测试、持久化和发布；初版固定 HTTP 配方不是后端能力上限。接受契约见 [generated-tools](product/generated-tools.md)。不授权宿主 shell、任意安装包、读取密钥、修改其他空间或新增费用。

构建过程的 UI 变化来自实际模型布局轮廓与源码事件，再过渡到完整隔离预览。未完成的源码不执行，不能用计时动画伪装进度。验收需要三种真实模型生成的不同页面交互、新工具执行与复用、保留数据/URL的后续修改、访客同步和英文 UI。高级绕过复现暂停；继续普通功能、权限和已有隔离证据验证。当前正在实施，未声称真实生成/上线。

## 2026-10-03 · 用户修订：通用代码生成与可见构建过程

用户明确纠正：不是为 Tinder 增加一个专用组件，而是“我说任何需求，它都能想办法给我生成出来”的产品体验。后续交付以通用网站生成链路为主：理解需求、规划界面与数据、生成 HTML/CSS/JavaScript、隔离预览、实际检查/修正、发布并保留 URL 与数据。现有可复用组件是可选材料，不能再成为拒绝普通前端需求的上限。

本修订取代下文首版中“只允许已注册组件、不生成源码”的产品范围限制。生成的浏览器代码须隔离于 LivingForma 主页面和服务端；不授权宿主 shell、任意 npm、凭据暴露或新增费用。外部账号、真实服务权限和物理设备仍按实际能力说明并处理，不能承诺所有外部需求必然完成。滑动照片仅作为一个跨类别验收输入，不能用关键词硬编码模板代替通用生成。

新增必须验收：至少三种不同交互需求通过同一真实 Agent 代码生成链路得到可运行网站；用户能看到真实生成阶段、代码/界面预览、错误与修正；至少一次后续修改保留 URL 和已写记录；未通过检查的候选不替换当前网站。完整 English 产品 UI。LF220/222 本地 API/Studio 已完成；真实 Pi、工具、动态 UI 整合验收待完成。生产403补丁已独立交付。

## 1. 愿景与产品边界

LivingForma 的中心设计是 Jarvis 式的个人软件助手：用户通过文字或语音表达意图，它理解需求、在用户主动启用时观察环境，并持续改造一个已经运行的网站。每个空间拥有持久的业务数据、受控能力和当前界面定义；界面可以改变，数据与链接继续存在。产品优先服务通用需求；读书记录、习惯打卡是验证数据保留与界面演化的起点，未来可切换到相机观察等交互场景。

MVP 的承诺是：**描述需求即可组合已注册组件与能力生成 App；之后持续修改字段、布局、交互和场景，数据与链接保留，其他访问者同步看到更新。组件目录持续扩充，不把首批四个组件当作永久上限。** 首轮演示已确定用读书记录与习惯打卡两个不同类别验证这套通用运行时；任务管理、预算追踪、轻量 CRM、签到、投票仍是其他可选示例，不构成固定产品流程。

“通用生成”指同一套声明式运行时能组合出不同类别的 App，并在后续请求中安全演化。它**不等于**生成任意 React/后端源码、运行模型生成的命令、安装包，或保证支持所有领域需求。运行时无法表达的需求形成能力扩展请求：Frontend 实现组件及变体，Agent 更新能力目录，Backend 校验 schema/权限，QA 验证后发布注册版本。不能把尚未开发的组件说成已经支持；也不能以四种组件为由长期把产品限制成表单后台。

用户进一步明确两条主线：**前端的可玩性与形态变化、后端通过 Pi 创建并复用工具。** 团队主动收集并分类 user cases，提前开发一批可复用的前端组件与元数据，由 Agent 判断如何组合、绑定数据和工具；样例用于发现能力缺口，而非变成固定模板。见 [场景—组件—工具地图](product/use-case-capability-map.md)。

## 3. 角色与核心用户故事

| 角色 | 核心行为 | 权限边界 |
| --- | --- | --- |
| 空间所有者（Owner） | 使用 Google 登录后创建空间；描述要做的 App；提出字段、布局、动作或外部能力的后续修改；管理数据 | 只有映射为该空间 Owner 的已登录用户能发布应用定义变更及启用外部能力 |
| 访客（Visitor） | 无需登录浏览公开的网站与已公开的数据，实时看到允许公开的界面更新 | 看不到编辑圆圈；没有写入、发布、私有记录或付费推理权限 |
| 参与者（Participant） | 写入时使用 Google 登录；按空间的参与策略录入或修改业务数据 | 登录不自动成为 Owner；写入仍需满足该空间权限，不能注册工具或修改网站 |

Google OAuth 是已确定的写入/管理登录入口；具体 provider 配置、回调与会话机制仍待实现。这里的 admin 指该网站的 Owner，不是所有已登录用户。公开浏览仅返回公开投影，不能因为匿名可读就暴露 Owner 草稿、私密字段、凭据或其他空间数据。后端须把 Google 身份映射为内部用户，并根据空间成员关系决定 Owner / Participant 权限；仅凭登录或持有共享 URL 不得取得 Owner 权限。登出或会话失效后，写入和管理操作必须被拒绝；公开网站仍可浏览。Participant 是否开放注册即写、邀请制及公开字段范围在空间权限契约中明确。

## 4. 通用生成与演化流程

1. Owner 使用 Google 登录并创建空间；点击左上角小圆圈，圆圈扩展到屏幕中央成为文字/语音输入入口，输入例如“做一个团队读书记录 App，能添加书名、作者和阅读状态”。系统依据受限字段类型、组件与动作目录，产出实体 schema、界面 AppSpec 和允许的业务动作。
2. 提交后入口回到角落，网站占据主画布；访客只有网站本身，没有聊天侧栏、底部编辑条或 Owner 圆圈。服务端校验规格后保存第一个版本；运行时渲染表单、列表/卡片和筛选等已支持组件。用户创建的书籍记录进入持久状态，刷新仍在。
3. Owner 继续输入“加评分字段，把已读书按评分排序，并突出我正在读的书”。Planner 针对当前版本生成 patch，不重建整个 App；新增字段采用安全默认值，旧记录仍可读取。更改布局、标签或展示方式也不删除数据。
4. 第二个浏览器无需登录即可打开公开共享 URL。Owner 发布新版本后，访客界面自动更新并提示“Owner 刚更新了界面”；访客写入时再登录并获得空间允许的参与权限，更新记录后双方看到同步数据。断线重连从服务端获取最新快照。
5. 当 Owner 请求已支持动作目录以外的外部服务时，系统识别能力缺口。MVP 首个示例待用户选定，优先选择只读 HTTP GET 查询：生成受限 ToolSpec，校验、测试并经 Owner 启用后注册；重复请求复用该工具。若需求需要 POST 等写入或外发动作，先明确告知超出首版范围，待权限、幂等与重试策略设计完成后再扩展。
6. 为证明通用性，再用**同一套运行时**创建习惯打卡空间，与读书记录空间形成已选定的首轮演示组合。两个空间各有自己的 schema、数据和界面，不互相污染；习惯打卡包含时间型 calendar-grid，展示日历/打卡分布，与读书 cover cards 明显不同；日期粒度、时区和重复打卡规则仍需契约明确。

7. 语音命令与文字命令进入同一意图/校验/发布链路。Owner 说“变成一个相机，告诉我发生了什么”，网站切到 camera 场景；当前设备用户点击开始并授予浏览器权限后取得画面，Gemini 理解，ElevenLabs 播报。停止会终止采集、推理和播放，其他浏览器不因收到新界面就自动开启自己的设备。

先把文字入口作为可测试的基础链路，再实现语音控制与相机播报里程碑；这是交付顺序，不再把语音/视觉长期列为可有可无。采样帧播报与真正双向 Live 会话分期验证，不能承诺零延迟或无限免费。产品方向与分期详见 [Jarvis 方向](product/jarvis-vision.md)。

## 5. 功能需求

| ID | 优先级 | 需求 |
| --- | --- | --- |
| F1 | 必须 | 公开网站匿名可浏览；创建、业务写入与管理需要 Google 登录，具体动作仍由空间权限控制。只有 Owner 有编辑圆圈，身份和 Owner/Participant/Visitor 权限由服务端执行。 |
| F2 | 必须 | 可扩展组件注册表：基础 form/list/cards/counter，加 cards cover/compact/hero、list dense/comfortable、枚举 emphasis highlight/pin/dim、calendar-grid 和 4–6 套精选皮肤 token。组件及版本有明确 schema/权限/降级信息，Planner 只引用已注册能力，不输出任意 CSS/JS。 |
| F3 | 必须 | 自然语言可创建初始 App，也可基于当前版本生成增量 patch，修改字段、布局或交互；所有结果经 schema、引用和权限校验后原子发布，失败保留上一可用版本。 |
| F4 | 必须 | 应用定义、版本及业务记录持久化。新增字段、重命名或隐藏字段应采用非破坏性演化；普通界面变更不得静默丢弃旧记录或删除旧字段值。 |
| F5 | 必须 | 同一空间的两个在线客户端自动收到应用版本和业务数据变化；断线重连能恢复最新快照。 |
| F6 | 必须 | 生成的 App 至少能完成该类别的基本数据动作，例如创建、查看、更新记录及一个有意义的领域动作；动作由受控目录执行，而不是任意模型代码。 |
| F7 | 必须 | 一个与用户共同选定的只读外部查询示例，通过 GET HTTP ToolSpec 完成“缺口识别 → 生成 → 校验 → 测试 → 注册 → 首次调用 → 再次复用”；执行记录可验证流程，不显示密钥。写入型外部服务暂缓。 |
| F8 | 必须 | 把“界面变形且数据不丢”和“另一浏览器同步看到变化”作为核心体验：真实高层阶段进度、发布成功后 Motion 过渡、变更摘要；保留草稿/焦点，普通记录事件只做局部反馈，支持 reduced motion。 |
| F9 | 应该 | 保留应用版本和变更摘要供 Owner 查看；一键回滚可在主链路稳定后实现。 |
| F10 | 必须 | 默认只启用经核实的免费额度；记录可能触发额度或收费的调用，免费额度耗尽时停止或降级并提示，不自动升级或产生费用。 |
| F11 | 必须（语音/视觉里程碑） | Owner 圆圈承载文字和语音，转录后的命令按相同权限生成/发布变更；可取消、打断、看见正在听/处理/说话的状态，保留文字入口。 |
| F12 | 必须（语音/视觉里程碑） | 支持 camera 场景的显式设备开启、视觉理解与语音描述；仅当前客户端采集，不通过业务 SSE 广播媒体，不默认持久化音视频；延迟、额度、断线与停止清理有真实证据。 |

MVP 的 ToolSpec 首选受限、只读 HTTP GET：目标地址、参数和超时受校验，密钥仅由服务端注入。写入型或消息发送类集成须在选定服务后单独设计目标范围、Owner 授权、幂等和失败重试，首版不承诺支持。删除、支付、部署、任意 shell 和模型生成代码执行不属于 MVP 动态能力。

首版 cover 指书名/文字排版与稳定哈希配色生成的封面感，不要求真实封面图或图片抓取；外部图片来源、URL 字段和回退需另外设计受控契约。匿名用户可以看到“登录后添加”等公开入口，但它不是可执行写入权限；认证后重取空间权限并由用户提交，不能直接自动重放未授权 mutation。

## 6. 验收场景

**A. 通用性：**本轮用同一运行时创建读书记录和习惯打卡两个空间。各自具有与需求相符的字段、组件和可执行动作；不能仅是改标题的硬编码模板。这是验证通用性的演示组合，不将产品限制为这两类；任务 → 签到 → 投票仍只是其他可选案例。

**B. 持续演化与数据完整性：**先在读书记录空间创建至少两本书，再用自然语言增加评分字段、按评分排序，并调整阅读状态的展示。URL 不变、页面不硬刷新；旧书记录和原有字段值保留并能在新版本读取。一次无效变更被拒绝后，旧版本仍可使用。

**C. 共享与恢复：**A 的 Owner 登录，B 作为匿名访客打开公开网站。B 不见编辑入口，A 发布后 B 显示更新提示。B 写入时登录并满足空间参与权限，A 收到记录变化。刷新和断线后恢复权威快照；登出后写入/管理被拒绝，公开浏览仍可用。

**D. 权限与能力：**Pi 驱动识别工具缺口、生成受限 ToolSpec、验证注册并供组件绑定结果；后端不能只提供预先写死的几个工具按钮。Google 登录只证明身份；非 Owner 的 Participant 直接请求发布 AppSpec 或注册 ToolSpec 被拒绝。演示所选只读外部查询首次调用完成受控创建流程，再次调用命中已注册工具；未授权目标、缺失密钥和无效参数被拦截，日志不泄露凭据。若没有真实服务授权，明确展示测试端点，不宣称已接入实际服务。

**E. Jarvis 与设备：**Owner 用语音改变 App，再切换到 camera；授权当前设备后，画面得到实际视觉描述并播报。新界面同步到 B 不得触发 B 的摄像头或播报 A 的画面。停止/离开场景后资源和过期描述全部清理。原读书数据仍可恢复；失败保留文字入口和最后有效 App。

**F. 成本与演示可信度：**未获用户确认前不触发收费。仓库说明可让评委访问或运行实际 MVP；三分钟以内的视频展示两个不同类别、其中一个的演化和多人同步。奖项或提交文案只陈述实际完成的集成。

## 7. 范围、顺序与取舍

**MVP 主链路：**自然语言 → 初始 AppSpec / 增量 patch → 校验 → 持久化 → 受限组件运行时 → 多人同步 → 基本业务动作；在这条链路稳定后，加入一个受控可复用的只读 GET HTTP ToolSpec。基础里程碑先验证文字输入；随后接上语音改站与摄像头播报，交付前独立验收这条新的核心体验。

**持续扩展：**更多字段/动作、图表、看板、版本回滚、角色专属视图、3D / SceneSpec、组件生成与测试注册流水线、轨迹提炼工具。语音与相机已经进入明确里程碑，不在本列表里延后。3D 是 stretch goal，不应妨碍通用 App 主链路。

**明确不做：**自建密码账号、多身份提供商和复杂组织权限（Google OAuth 登录本身是必需）、任意 npm 安装、宿主机命令执行、任意源码生成/执行、完整无代码编辑器、通用 3D 多人游戏。通用性以已定义的 schema、组件和动作目录为边界；对外集成以真实可验证的实现为准。

## 8. 成功标准

评委能亲手验证：**同一套系统生成不同类别的 App；界面在眼前变形且数据不丢，另一浏览器同步看到更新；Owner 通过语音改变网站，并启用可见的相机观察/播报场景。** 软件保留状态并持续演化，而不是每次提示后产生一个孤立的新网页。
