# LivingForma — Hackathon MVP 产品需求文档

状态：产品草案 · 2026-10-03

## 1. 愿景与产品边界

LivingForma 让用户用自然语言创建和持续改造一个已经运行的共享 App。每个空间拥有持久的业务数据、受控能力和当前界面定义；界面可以改变，数据与链接继续存在。产品优先服务通用的轻量业务需求，而不是预设某个活动场景。

MVP 的承诺是：**在已支持的字段、组件与动作范围内，描述需求即可生成可用 App；之后可继续修改布局、字段、交互和能力，多人看到同一版本与状态。** 首轮演示已确定用读书记录与习惯打卡两个不同类别验证这套通用运行时；任务管理、预算追踪、轻量 CRM、签到、投票仍是其他可选示例，不构成固定产品流程。

“通用生成”指同一套声明式运行时能组合出不同类别的 App，并在后续请求中安全演化。它**不等于**生成任意 React/后端源码、运行模型生成的命令、安装包，或保证支持所有领域需求。运行时无法表达的功能须明确反馈限制，或经过受控的能力扩展流程。

## 2. 已确认事实与拟议实现

**已确认：**项目名 LivingForma；GitHub 仓库为 fanxiaotuGod/livingforma；在启动规划时仓库只有 README，尚无可运行应用；livingforma.tech 的注册已核实（2026-10-03 注册、2027-10-03 到期）；DNS、部署和可访问性尚未验证。用户已决定优先通用 App 生成，并选择读书记录 + 习惯打卡作为首轮演示组合；MVP 要求 Google OAuth 登录；先使用免费额度，**任何收费发生前必须由用户确认**。以下功能都是待实现需求，而非当前产品能力。

**拟议、尚未锁定：**React / Next.js / TypeScript 与 Motion 构建界面；Node.js / TypeScript 后端；Gemini 规划声明式 AppSpec / ToolSpec，Pi 可作为 Agent 运行时；ElevenLabs 可加入语音输入或播报。Tiger Data 托管 PostgreSQL 是首选候选，前提是核实 Shared Free 的实际资格、额度和停止策略；共享截图中的 0.5 CPU 选项显示为收费路径，不应直接开通。目前未验证任何 Tiger Data 实例已创建。业务状态必须只有一个主数据源；如免费条件不合适，再评估其他 PostgreSQL 方案。实时传输方式仍需验证。Snowflake 仅可选用于应用变更与工具事件的非关键分析，不替代主数据库，也不阻塞 MVP。模型版本、平台和免费额度以集成时的实际可用性为准；不得自动切换付费层或启用会产生收费的服务。

## 3. 角色与核心用户故事

| 角色 | 核心行为 | 权限边界 |
| --- | --- | --- |
| 空间所有者（Owner） | 使用 Google 登录后创建空间；描述要做的 App；提出字段、布局、动作或外部能力的后续修改；管理数据 | 只有映射为该空间 Owner 的已登录用户能发布应用定义变更及启用外部能力 |
| 参与者（Participant） | 使用 Google 登录后打开共享链接；按当前 App 允许的操作录入、修改或查看业务数据；实时收到变化 | 不能修改应用定义、注册工具或取得 Owner 凭据 |

Google OAuth 是已确定的登录入口；具体 provider 配置、回调与会话机制仍待实现。后端须把 Google 身份映射为内部用户，并根据空间成员关系决定 Owner / Participant 权限；仅凭登录或持有共享 URL 不得取得 Owner 权限。登出或会话失效后，受保护操作必须被拒绝。

## 4. 通用生成与演化流程

1. Owner 使用 Google 登录并创建空间，输入例如“做一个团队读书记录 App，能添加书名、作者和阅读状态”。系统依据受限字段类型、组件与动作目录，产出实体 schema、界面 AppSpec 和允许的业务动作。
2. 服务端校验规格后保存第一个版本；运行时渲染表单、列表/卡片和筛选等已支持组件。用户创建的书籍记录进入持久状态，刷新仍在。
3. Owner 继续输入“加评分字段，把已读书按评分排序，并突出我正在读的书”。Planner 针对当前版本生成 patch，不重建整个 App；新增字段采用安全默认值，旧记录仍可读取。更改布局、标签或展示方式也不删除数据。
4. 第二个浏览器由另一位用户使用 Google 登录并打开同一共享 URL。Owner 发布新版本后，参与者的界面自动更新；参与者新增/更新记录后，双方看到同步后的数据。断线重连从服务端获取最新快照。
5. 当 Owner 请求已支持动作目录以外的外部服务时，系统识别能力缺口。MVP 首个示例待用户选定，优先选择只读 HTTP GET 查询：生成受限 ToolSpec，校验、测试并经 Owner 启用后注册；重复请求复用该工具。若需求需要 POST 等写入或外发动作，先明确告知超出首版范围，待权限、幂等与重试策略设计完成后再扩展。
6. 为证明通用性，再用**同一套运行时**创建习惯打卡空间，与读书记录空间形成已选定的首轮演示组合。两个空间各有自己的 schema、数据和界面，不互相污染；习惯打卡的最小字段与操作仍待团队明确。

文字流程先独立完成；语音是增强体验，不是 App 生成的前置条件。

## 5. 功能需求

| ID | 优先级 | 需求 |
| --- | --- | --- |
| F1 | 必须 | Google OAuth 登录/登出与服务端会话是进入空间和执行业务动作的前置条件；创建有稳定 URL 的空间，Owner 与 Participant 权限由服务端执行。 |
| F2 | 必须 | 用受限实体 schema、AppSpec 与组件注册表组合不同类别的轻量 App。初始目录至少覆盖文本/数字/日期/布尔等常用字段、表单、列表/卡片、计数与基本动作；超出目录的需求返回可理解的限制。 |
| F3 | 必须 | 自然语言可创建初始 App，也可基于当前版本生成增量 patch，修改字段、布局或交互；所有结果经 schema、引用和权限校验后原子发布，失败保留上一可用版本。 |
| F4 | 必须 | 应用定义、版本及业务记录持久化。新增字段、重命名或隐藏字段应采用非破坏性演化；普通界面变更不得静默丢弃旧记录或删除旧字段值。 |
| F5 | 必须 | 同一空间的两个在线客户端自动收到应用版本和业务数据变化；断线重连能恢复最新快照。 |
| F6 | 必须 | 生成的 App 至少能完成该类别的基本数据动作，例如创建、查看、更新记录及一个有意义的领域动作；动作由受控目录执行，而不是任意模型代码。 |
| F7 | 必须 | 一个与用户共同选定的只读外部查询示例，通过 GET HTTP ToolSpec 完成“缺口识别 → 生成 → 校验 → 测试 → 注册 → 首次调用 → 再次复用”；执行记录可验证流程，不显示密钥。写入型外部服务暂缓。 |
| F8 | 应该 | 发布新版本时用稳定组件 ID 呈现连续的过渡动画，并展示高层进度；不暴露模型内部推理。 |
| F9 | 应该 | 保留应用版本和变更摘要供 Owner 查看；一键回滚可在主链路稳定后实现。 |
| F10 | 必须 | 默认只启用经核实的免费额度；记录可能触发额度或收费的调用，免费额度耗尽时停止或降级并提示，不自动升级或产生费用。 |

MVP 的 ToolSpec 首选受限、只读 HTTP GET：目标地址、参数和超时受校验，密钥仅由服务端注入。写入型或消息发送类集成须在选定服务后单独设计目标范围、Owner 授权、幂等和失败重试，首版不承诺支持。删除、支付、部署、任意 shell 和模型生成代码执行不属于 MVP 动态能力。

## 6. 验收场景

**A. 通用性：**本轮用同一运行时创建读书记录和习惯打卡两个空间。各自具有与需求相符的字段、组件和可执行动作；不能仅是改标题的硬编码模板。这是验证通用性的演示组合，不将产品限制为这两类；任务 → 签到 → 投票仍只是其他可选案例。

**B. 持续演化与数据完整性：**先在读书记录空间创建至少两本书，再用自然语言增加评分字段、按评分排序，并调整阅读状态的展示。URL 不变、页面不硬刷新；旧书记录和原有字段值保留并能在新版本读取。一次无效变更被拒绝后，旧版本仍可使用。

**C. 共享与恢复：**浏览器 A 的 Owner 与浏览器 B 的 Participant 分别通过 Google 登录并打开同一空间。A 发布版本后 B 自动看到新界面；B 修改一条记录后 A 看到数据变化。刷新与断线重连后两端均恢复到同一最新状态。登出或会话失效后，受保护动作不可继续执行。

**D. 权限与能力：**Google 登录只证明身份；非 Owner 的 Participant 直接请求发布 AppSpec 或注册 ToolSpec 被拒绝。演示所选只读外部查询首次调用完成受控创建流程，再次调用命中已注册工具；未授权目标、缺失密钥和无效参数被拦截，日志不泄露凭据。若没有真实服务授权，明确展示测试端点，不宣称已接入实际服务。

**E. 成本与演示可信度：**未获用户确认前不触发收费。仓库说明可让评委访问或运行实际 MVP；三分钟以内的视频展示两个不同类别、其中一个的演化和多人同步。奖项或提交文案只陈述实际完成的集成。

## 7. 范围、顺序与取舍

**MVP 主链路：**自然语言 → 初始 AppSpec / 增量 patch → 校验 → 持久化 → 受限组件运行时 → 多人同步 → 基本业务动作；在这条链路稳定后，加入一个受控可复用的只读 GET HTTP ToolSpec。先让文本输入可靠，再考虑语音。

**可扩展：**ElevenLabs 语音交互、更多字段与图表、版本回滚、角色专属视图、3D / SceneSpec、组件自学习、轨迹提炼工具。3D 是 stretch goal，不应妨碍通用 App 主链路。

**明确不做：**自建密码账号、多身份提供商和复杂组织权限（Google OAuth 登录本身是必需）、任意 npm 安装、宿主机命令执行、任意源码生成/执行、完整无代码编辑器、通用 3D 多人游戏。通用性以已定义的 schema、组件和动作目录为边界；对外集成以真实可验证的实现为准。

## 8. 成功标准

评委能亲手验证：**同一套系统生成不同类别的 App；其中一个 App 在有数据后继续改变形态；其他人同步看到并操作；后端新增的受控能力可以复用。** 软件保留状态并持续演化，而不是每次提示后产生一个孤立的新网页。
