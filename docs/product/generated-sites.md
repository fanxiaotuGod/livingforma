## Generation API — Backend LF220

All generation mutations use current signed-in Owner, exactOrigin and CSRF. Durable jobs are keyed by space/user/requestId with a payload fingerprint; retry returns the same job without another model call. Preserve original session association and recheck it after model work; revoked original sessions cannot yield late previews/publications. GET/events are Owner-only, not ordinary public SSE.

- POST `/api/spaces/:slug/generations` generationRequestSchema → GenerationJob; return promptly and begin bounded async generation. Store original base version and one-process bounded worker/lease. Server restart or expired lease must produce a truthful interrupted/failed state, never silently re-run a provider request.
- GET `/api/spaces/:slug/generations/:id` → GenerationJob.
- GET `/api/spaces/:slug/generations/:id/events?after=N` → finite-sequence SSE `generation` events; replay durable sanitized events, periodic session/Owner checks, close on revocation. Return job via normal GET for reconnect recovery; reconnect never starts generation again.
- POST `.../:id/preview` generationPreviewSchema → GenerationJob. Bind to exact validated sourceRevision. Actual browser ready/error report sets `checked` or invokes at most one repair using concrete errors. Client report is an Owner preview check, not a claim all generated behaviors are exhaustively verified. Preview writes are disabled.
- POST `.../:id/publish` generationPublishSchema → `{snapshot,job}`. Require checked exact revision, current valid original session/Owner, unchanged base version, revalidate evolution/source, then atomic publish/event/history. Idempotent requestId. No partial schema/source commits. Keep tools/records safe.
- POST `.../:id/cancel` → GenerationJob, abort work and suppress late success. Completed publication is not retroactively cancelled.
- GET `/api/spaces/:slug/versions` → `{versions:DefinitionVersionSummary[]}` Owner-only; persist immutable complete versions when publishing. Version restore is a separate future mutation until safely specified.

AppOptions adds optional `siteGenerator?:SiteGenerator`; server wires the Agent export after LF221. Tests inject offline generators. Current POST/proposals remains for trusted composition/backward compatibility; the studio uses general generation as the default ordinary text path.

## Browser frame delivery

Use GET `/api/generated-frame?space=SLUG&generation=JOB&revision=N&channel=RANDOM` for validated candidate preview (stage `preview` or `checked`; the frame must load before the browser can report its check), or `?space=SLUG&version=N&channel=RANDOM` for the actual published version. Preview access is Owner/original-session scoped; published access uses space read authorization. A random channel is a bridge correlation ID, not authorization. Do not redirect this route. Parent CSP pins frame-src to the exact same-origin `/api/generated-frame` path. The child response replaces the normal app CSP/X-Frame-Options intentionally: `frame-ancestors 'self'`, `sandbox allow-scripts`, `default-src 'none'`, `script-src 'unsafe-inline'`, `style-src 'unsafe-inline'`, `img-src data: blob:`, `connect-src 'none'`, `frame-src 'none'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. No allow-same-origin, popups, forms, downloads, top navigation, external scripts or eval. Set Referrer-Policy no-referrer and Permissions-Policy disabling camera/microphone/geolocation/other device/network APIs where supported.

Do NOT use nonce/hash authorization for the untrusted child scripts: an actual Chrome154 adversarial test copied the nonce to an external script and fetched it. Inline-only without source hosts blocked that attack. Served response policies are used instead of srcdoc inherited CSP. Actual Chrome154 test with parent exact frame-src blocked external child self-navigation (zero receiver requests), and child cookie/localStorage access threwSecurityError with opaque message origin null. Expand these checks before release. Sandbox alone does not guarantee CPU isolation or all WebRTC restrictions; block dangerous APIs in a trusted bootstrap before generated scripts, test fresh realms and outbound attempts, and do not claim an unproven complete network/CPU sandbox.

### Accepted hardening after an actual fresh-realm escape

Root verified that an injected nested iframe `srcdoc` could execute a native RTC constructor even with frame-src none and an immutable createElement stub. Direct parent access to that fresh realm was blocked, but its own script could execute. Backend is therefore adding `require-trusted-types-for 'script'` and an exact trusted-types policy-name allowlist (no duplicate policies), with a private bootstrap loader. HTML/CSS/JS travel as escaped source data; generated code is inserted only after native Trusted Types support and policies are installed. Unsupported browsers show an English compatibility message and execute no generated source.

The bootstrap alone holds the raw parser/initial-script policies. A default HTML policy supports common generated `innerHTML` interactions through strict inert parsing and HTML/limited-SVG allowlists, stripping nested frames, active elements, inline event handlers, srcdoc and dangerous URLs; templates/foreign namespaces need recursive validation. New script strings/URLs and policy recreation are denied. Initial source serialization escapes HTML script boundaries. This is accepted implementation direction, pending actual adversarial checks and independent QA. The existing opaque origin, CSP, public-only bridge and no host execution remain required; do not claim complete browser CPU isolation.

## Bridge — Frontend LF222 / Backend bootstrap

Backend renders a trusted bootstrap plus bounded artifact. Bootstrap exposes immutable `window.lf` and creates a MessageChannel handshake to parent with channel/version; parent validates exact iframe.contentWindow, correlation ID and current source/session/page revision before accepting its port. Discard/close old ports on reload, navigation, auth change or source replacement. No credentials ever sent to child. Every request has a unique correlation id and strict payload/size/type validation; arbitrary postMessages cannot choose another space, endpoint or token.

`await lf.ready` returns `{records,schema,actions,role,permissions,preview}` containing only public fields and public action bindings. `lf.subscribe(callback)` observes updated projected state. `lf.create(values)`, `lf.update(recordId,values)`, `lf.remove(recordId)`, `lf.checkIn(recordId,fieldId)` map to host-selected matching bound action, server versions and protected mutation; no arbitrary API path. Preview returns a clear read-only error; anonymous writes open host Google login without auto-replay. Host confirms destructive delete. Frame cannot invoke auth/admin/definition/provider/ToolSpec registration. Local UI interactions are unrestricted within the isolated document. Runtime `error`/unhandledrejection and explicit `lf.reportReady()` are bounded diagnostic reports; no console dump or model reasoning.

Photo assets: `lf.pickImage()` opens a trusted host file chooser and uploads only the user's explicit selected raster file, returning `{assetId,dataUrl}`; `lf.image(assetId)` resolves an authorized stored raster to dataURL. Store `asset_ID` as a text record value or artifact.assetIds, never raw base64 in ordinary records. Backend POST `/api/spaces/:slug/assets` body `{mimeType,dataBase64}` writer+CSRF → `{assetId,dataUrl}`; GET `/api/spaces/:slug/assets/:id` → same. Limit decoded512KiB, max4096px dimensions, PNG/JPEG/WebP magic+dimensions, noSVG/HTML; quota20MiB per space, no paid storage fallback. Bound rate/body limits. Public read only for assets referenced by published records/artifact; unpublished assets are uploader/Owner scoped. No external image fetcher/SSRF. Frontend scales/compresses actual selected images if needed and shows honest size errors.
