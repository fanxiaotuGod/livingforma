# LivingForma：会对话、会观察、会改变形态的网站

更新：2026-10-03。用户确认的产品方向；本文不是已实现功能清单。

## 产品要让人记住什么

界面在眼前变形，已有数据一条没丢；另一浏览器同步看到变化。更长期的中心体验是一个 Jarvis 式助手：用户通过文字或语音表达意图，网站成为当下需要的工具，也能在用户主动启用设备后观察环境并作出语音回应。

读书记录与习惯打卡是第一组验收例子。通用性还体现在交互方式和场景的变化，不应固定成“表单 + 卡片列表”的换标题模板。

用户随后再次明确：产品重点是前端可玩、可变形的组件组合，以及后端通过 Pi 创建和复用工具。主动分类用户场景，先建设丰富的可信组件库，让 Agent 按意图组装。语音/相机体现这两条主线；不是把项目收缩成一个对话或相机产品。详见 [场景能力地图](use-case-capability-map.md)。

## 已确认的交互与权限

- **Owner/admin** 指这个网站的所有者，不是所有已登录的人。只有有编辑权限的 Owner 看到左上角小圆圈。
- 点击圆圈后，它从角落扩展到中央，承载文字输入和语音会话；可取消、提交、打断，退出后回到角落。网站占主画布，不采用固定聊天侧栏，也不采用第三方建议的固定底部命令条。
- 访客无需登录浏览公开网站，只看到网站本身。写入时使用 Google 登录，再按该网站的参与权限执行；登录不能使访客成为 Owner。
- 公开浏览使用明确的公开数据投影，不暴露私密字段、Owner 草稿、密钥或其他空间数据。是否对任何登录者开放特定写操作，仍由空间权限策略确定。
- 语音命令和文字命令进入同一授权、规划、校验、发布链路。界面显示的阶段来自实际进度，发布成功后才播放变形；不使用假进度冒充模型结果。

## 组件需要持续成长

用户接受扩展目录，初始目标包含：cards 的 cover/compact/hero 变体、list 的 dense/comfortable 密度、枚举强调规则 highlight/pin/dim、calendar-grid 时间组件、4–6 套精选皮肤。具体值、schema 和组合限制在共享契约中定稿；模型选择 token，不输出任意 CSS。

新增组件的流程是：真实需求 → 能力缺口 → schema/组件/权限设计 → 实现与预览 → 数据/可访问性/性能验证 → 版本化注册 → Planner 可以发现和复用。Frontend 主动提出扩展，Coordinator、Backend、Agent 一起确认契约。这个流程支持持续成长，不等于当前运行时可以直接安装依赖或执行任意生成代码。

相机、麦克风、语音输出是明确的设备/服务能力，不能假装是四种数据组件的一种外观。它们需要自己的生命周期、权限和失败行为。3D 仍为后续扩展方向。

## “变成相机，告诉我发生了什么”

Owner 发出命令 → 规划并发布 camera 场景 → 当前设备用户点击开始并授予浏览器权限 → 浏览器采集画面 → Gemini 视觉理解 → ElevenLabs 播报简短描述。

相机画面不是新的管理员指令。来自画面、网页或工具结果的文字不能自行授权发布、调用工具或更改权限。媒体会话属于当前客户端，不能通过业务 SSE 广播画面、录音或自动启动其他访问者的摄像头。停止、离开场景和登出时清理相应采集/推理/播放；切回读书界面仍保留记录。

先验证有背压的采样帧描述与流式语音，显示实际状态并测量延迟；真正双向低延迟 Live 会话是下一档实现。用户说“实时”不代表我们可以声称每帧理解、零延迟或免费无限调用。账号实际模型权限与额度未测试，收费前确认。

## 技术建议与分期

coordinator 推荐 **Vite + React + TypeScript SPA**，搭配 Motion、Tailwind、Radix；共享 schema 使用 Zod，服务端为独立 Node.js/TypeScript API（Fastify 候选）。该建议替代旧的 Next.js 默认倾向，最终包版本和启动方式在 LF-100 验证并锁定。

Vite 对本项目的价值是直接服务大量浏览器交互；前后端可在代码上分包，而由同一个 Node 服务在生产同源提供静态页面、OAuth、API、SSE，按需增加 WebSocket。开发代理不能当成生产路由。Next.js 也能做 SPA；未来若每个生成页面的 SEO、服务端 HTML 或动态分享元数据成为关键需求，再评估它的价值。[Vite 部署](https://vite.dev/guide/static-deploy)、[Next.js SPA](https://nextjs.org/docs/app/guides/single-page-applications)

1. **设计与实验场**：画 5–6 个关键帧，优先验证 Owner orb、读书界面增加评分/排序、B 浏览器提示更新、习惯 calendar-grid。用 fixture 和本地双标签同步探索，明确标记模拟；不把“先设计一天”当作 hackathon 的固定要求。
2. **真实基础链路**：LF-100 → 各角色 → LF-150，接入公开浏览/Google 写入、持久化、模型提案、真实 SSE，证明同一数据与 URL 持续存在。
3. **Jarvis 里程碑**：LF-180/181/182 → LF-185，把真实语音改站、camera 视觉理解与 ElevenLabs 播报接通，验证中断、停止、额度和客户端隔离。文字入口继续作为可靠回退；该阶段不是永远可选的装饰。
4. **验收和上线**：LF-160 独立检查后，LF-170 发布到 livingforma.tech。若实际 API 权限/免费额度阻塞，报告缺失证据与可行方案，不把 mock 说成已完成。

前端细节见 [体验方向](../frontend/experience-direction.md)、[Skills 使用约定](../frontend/skills-guide.md)，模型/语音链路见 [多模态方案](../agent/multimodal-plan.md)。后续用户已授权并完成本机 `frontend-dev` / `animations` 安装，按前端 skills-guide 使用项目适配；其他 3D/GSAP 技能仍待实际需要再评估。
