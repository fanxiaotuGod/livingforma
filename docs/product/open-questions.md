# LivingForma — 待决产品问题

状态：2026-10-03。以下“建议默认值”是供团队验证的方案，不代表已决定或已实现。

## 已确认约束

- 产品优先通用 App 生成与持续演化；首轮演示已确定为读书记录 + 习惯打卡。它们是验收示例而非产品边界；任务、签到、投票等仍只是其他可选案例。
- 上线先使用免费额度；**任何收费发生前必须获得用户确认**。具体平台、模型、免费配额与限流策略尚未决定。
- 通用生成只覆盖受限 schema、组件、动作和声明式工具；不运行任意模型生成代码。3D 属于 stretch goal。

## 待决项

| 优先级 | 问题 | 建议默认值 / 验证方式 |
| --- | --- | --- |
| P0 | 首版受支持的字段、组件、动作目录有哪些？“无法表达”时怎样回应？ | 先支持常见数据字段、表单、列表/卡片、计数与创建/查看/更新；用读书、习惯、轻量 CRM 等跨类别请求测试目录是否通用。缺少能力时说明具体边界，不偷偷生成代码。 |
| P0 | 已选读书记录 + 习惯打卡；两类的最小字段、校验与业务动作如何定义？ | 读书先录入书名/作者/阅读状态等记录，再加评分并排序，验证旧值保留。习惯空间需明确频率和每次完成记录的粒度；两类必须由同一受限运行时生成。 |
| P0 | schema 变更如何安全处理已有记录，尤其是重命名、删除和类型变化？ | 加字段用默认值或空值；重命名保留字段映射；隐藏不等于删数据。破坏性迁移先拒绝或要求单独明确操作。 |
| P0 | 谁是 Owner？共享 URL 怎样避免赋予参与者编辑应用的权限？ | 演示阶段用服务端保存的 Owner 身份或独立管理令牌；Participant 链接不得携带 Owner 凭据，直接调用变更接口应被拒绝。 |
| P0 | 采用哪套数据库与实时机制？原始 brief 建议 Supabase，奖项方向考虑 Tiger Data。 | 先做“生成空间 → 写入记录 → 两浏览器推送”的纵向验证，再锁定单一事实来源；可比较 Tiger Data + SSE/WebSocket 与 Supabase 方案。 |
| P0 | 可复用 ToolSpec 接哪个外部服务？由谁提供凭据、授权有副作用的调用？ | 由用户和团队按实际需求选择；先用受控测试端点验证注册与复用，再接真正服务。不得把测试调用描述成真实集成。 |
| P0 | 如何确保免费优先并阻止意外收费？ | 为所有云服务核对当前免费条件、设置应用级请求上限和用量可见性；免费额度耗尽时暂停/降级。付费升级、充值或启用收费资源前必须向用户展示具体方案并取得确认。 |
| P0 | livingforma.tech 是否已完成 DNS、HTTPS 与部署？ | 上线前从未登录的设备访问并演示；不可用时保留可访问的备用 URL。 |
| P1 | Gemini 实际使用哪个可用模型、调用方式和免费配额？Pi 是否兼容？ | 以端到端测试为准；模型名和额度做成配置，不在产品文案中写死。 |
| P1 | ElevenLabs 用于输入、播报，还是两者？ | 文字主链路完成后加入至少一条可演示语音路径；仅注册账号不算集成。 |
| P1 | 版本回滚对业务数据有什么影响？ | 先保存版本历史；如做回滚，优先只回滚界面定义，业务数据回滚需单独设计。 |
